# 06 — UI/UX・SF調デザイン設計

## 1. デザインコンセプト

**UNVEIL / Research Observatory** — 「隠された構造を観測し、層を剥がして理解する研究端末」。映画的な飾りより、精密な情報設計と静かな緊張感を重視する。ユーザーのUI資料は未受領。本書は情報設計と仮トークンであり、最終ルックの確定稿ではない。

- プロらしさ: 揃ったグリッド、余白、文字階層、状態・操作の一貫性、情報密度の制御。
- SFらしさ: 深い濃紺、控えめなシアン、細い境界、計器風の小さなラベル、層/履歴の構造図。
- 避けるもの: 常時点滅、過度なグロー、全文等幅、大量の疑似ログ、根拠のない「危険度ゲージ」、装飾のための読みにくい斜体。
- 主役は原本・根拠・差分。装飾はコード領域やWIKI本文の背後に置かない。

## 2. 情報アーキテクチャ

```text
UNVEIL
 ├─ Dashboard      最近の研究/新規取込/対応状況
 ├─ Analyze        概要/根拠/変換/比較
 ├─ Sessions       保存研究/再開/削除
 ├─ Knowledge      WIKI/分類/年表/用語/教材
 ├─ Reports        出力済みレポート/再出力
 └─ Settings       解析上限/表示/保存/バージョン/隔離診断
```

アクティブセッションはアプリ全体で保持し、WIKIへ移動しても失わない。Reportsは出力ジョブと保存先メタデータの管理であり、原本を勝手に複製する場所ではない。高度解析など未実装メニューは紛らわしい有効ボタンにせず、将来予定として明示するか非表示とする。

## 3. レイアウト契約

- 基準画面1440×900、最小作業画面1366×768を目標とする。
- 左サイドバー: 232px、折畳み72px。アイコン＋名称、現在地、下部に設定/版/隔離状態。
- 上部ヘッダー: 64px。セッション名、原本/派生物識別、静的モード、保存状態、主要操作。
- コンテンツ: 24px余白、8px系スペーシング、カード間16〜24px。読解領域は必要に応じて幅を制限する。
- 右のInspector: 320〜380px、可変/収納可能。メインが狭い場合は引出しへ変える。
- 下部ステータス: 28px、工程/経過/資源制限/エラー通知。長いログは別パネルへ。
- 200%ズーム/幅1024px未満ではサイドバーとInspectorを収納し、比較を縦積み/タブにする。WIKIは幅320px相当までリフローし、コードだけ局所横スクロールを許可。

```text
┌────────────┬─────────────────────────────────────────────────┐
│ UNVEIL     │ Session / specimen.js    STATIC   未保存  保存   │
│            ├─────────────────────────────────────────────────┤
│ Dashboard  │ 概要    根拠    変換    比較                     │
│ Analyze    ├───────────────────────────┬─────────────────────┤
│ Sessions   │ 解析サマリー              │ 選択中の根拠         │
│ Knowledge  │ 兆候 / coverage / 制約    │ byte範囲・観測値     │
│ Reports    │                           │ 反証・方式候補       │
│            │ 原本 / Text・Hex・AST     │ WIKIで学ぶ           │
│            │                           │ 変換をプレビュー     │
│ Settings   ├───────────────────────────┴─────────────────────┤
│ v / 隔離   │ 検知完了   9/9検査   未解析: なし（対応範囲内） │
└────────────┴─────────────────────────────────────────────────┘
```

これは構成ワイヤーフレーム。画面の確定に用いるピクセルモック/画像ではない。

## 5. 画面ごとの内容と操作

### S01 Dashboard / 初回

「ファイルを選択」「ここにドロップ」「教材から始める」を主導線にする。静的解析、外部送信なし、一時スナップショット保存、対応形式、最大サイズを簡潔に説明。最近のセッションは保存済みだけ表示し、初回に架空の分析件数を置かない。

### S02 取込確認

ファイル名、サイズ、推定形式、保存モードを表示。実体と拡張子の不一致は注意として表示し、自動的に危険としない。取込拒否時は許容サイズや形式の理由を示す。取込と解析開始は分離し、ファイル選択だけで重い変換を実行しない。

### S03 Analyze / Overview

上段は「難読化兆候」「関連する表現変換」「解析範囲」「解除支援」の四項目。下段に方式候補、根拠件数、可読性に関する観測、未解析範囲を表示。数値スコアは説明を開けるようにし、総合の『安全度』へ変換しない。

主要操作は状態依存: 未解析→「静的解析を開始」、解析中→「停止」、結果あり→「根拠を確認」。無関係な操作を同時に強調しない。

### S04 Evidence

左: Finding一覧（方式/区分/範囲/証拠強度）。中央: Text/Hex/AST読取専用ビュー。右: 選択根拠、観測値、反証、適用ルール版、WIKIへのリンク。候補選択とbyteハイライトを同期する。AST未対応は空グラフではなく未対応説明。

### S05 Transform

候補ごとに「入力範囲」「実施する操作」「前提」「変換で失われる情報」「最大出力」「検証方法」を表示。Preview後は未承認透かしラベル、原本との差分、予算到達情報を表示。承認済み計画にのみ「適用して派生物を保存」を有効化する。

「自動チェーン」は既定OFF。許可方式・深さ・出力上限を具体的に示して承認する。「万能解除」「完全復元」の文言は使用しない。

### S06 Compare / History

原本と選択派生物の左右比較、追加/削除/変更を色＋記号で示す。bytes長・文字コード・ハッシュ・適用順を表示。mappingがapproximate/unmappedならその理由を明示する。バイナリ結果はHex。履歴DAGと表形式の代替ビューを用意し、画面幅が狭い場合は縦比較。

「元に戻る」は原本を再選択する操作で、既存派生物の上書き削除ではない。枝から再変換すると新しい履歴を作る。

### S07 Knowledge

入口は検索、分類、年表、学習コース。記事はパンくず＋タイトル＋概要＋本文＋目次＋関連記事。現版の検知/解除対応をバッジで示す。年表は横長図だけでなく年代順リストも提供し、年不明の背景は別章にする。

「現在の解析に戻る」「教材で試す」を別操作にし、実ファイルと教材を取り違えない。出典・引用箇所・改訂履歴は折り畳めるが隠蔽しない。

### S08 Sessions / Reports

名前、日時、入力ハッシュ短縮、エンジン版、状態、機密区分を一覧化。再開時のルール版違いは、旧結果保持/新規再解析の選択肢を示す。削除は関連する原本スナップショットと派生物の範囲を確認。

書き出しは内容プレビューを先に示す。ファイル名/パス/抜粋/ハッシュ/原本同梱を個別選択。既定は原本と本文の非同梱。マスクによる再現性低下も表示する。

### S09 Settings

解析上限、保存、配色/文字サイズ、言語、WIKI/エンジン版、隔離自己診断、対応一覧。安全上限より高い値は入力不可。MVPで通信が必要なのは明示的な外部リンク/更新ファイル取得を別アプリで行う場合だけと説明する。

## 6. 状態・文言のルール

| 内部状態 | 表示例 | 次の操作 |
|---|---|---|
| no_indicators + full | 対応検査では難読化の兆候は見つかりませんでした。安全性や不在の証明ではありません | 実施検査を確認 |
| no_indicators + partial | 調べた範囲では兆候なし。未解析範囲があります | 範囲/制限を確認 |
| inconclusive | 判定できません。候補と不足している根拠を確認してください | 根拠/WIKI |
| unsupported | この形式の内部解析は現版では未対応です | 対応一覧 |
| transformed | 選択した変換を適用しました。全層の解除は未確認です | 比較/未解除候補 |
| validation.failed | 検証に合格しませんでした。推奨出力にはしません | 失敗理由/原本 |
| cancelled | 停止しました。確定済みの結果のみ残しています | 結果確認/新規再試行 |
| sandbox unavailable | 隔離環境を利用できないため解析を開始できません | 診断/WIKI |

Toastだけで重要な失敗を済ませない。該当パネル内に理由と回復手順を残す。処理未開始に『0%完了』の疑似アニメーションは不要。

## 7. インタラクション・アクセシビリティ

- Tab順はサイドバー→ヘッダー→タブ→メイン→Inspector。領域スキップ、可視フォーカス、モーダルのfocus trapと復帰先を実装する。
- `Ctrl/Cmd+O`ファイル選択、`Ctrl/Cmd+K`ナビ/検索、`Esc`ダイアログを閉じる。Esc単独で走行中解析を黙って中止しない。
- ボタンの視覚高さ40px程度、操作対象は最低24×24 CSS pxを満たし、主操作は44pxを推奨する。
- アイコンだけの場合はaccessible nameを付ける。チャートは数値表、DAGは履歴表、色付き差分は記号/文言を併設する。
- 進捗のlive regionは節目で通知し、秒単位の細かい変化を読み上げ続けない。
- 画面遷移/展開は120〜180msのopacity/位置補間を暫定案とする。reduce-motionではアニメーション/scan効果を停止する。
- コードの双方向制御文字、不可視文字、改行を可視化できるようにする。コピー時は元bytesに基づく文字列か表示文字列かを選び、勝手に正規化しない。

## 8. UI資料受領後の進め方

1. 参照画像/デザインファイル、対象OS、最低画面幅、ロゴ/フォント使用権を確認。
2. 本仕様の画面/状態と照合し、不足するエラー/中止/未対応/長文のデザインを追加。
3. トークンと基礎部品→Overview/Evidence→Transform/Compare→WIKIの順に高精細化。
4. ダミーデータと実解析結果を区別したプロトタイプで、5名以上を目安にタスク試験。
5. ユーザー承認とアクセシビリティ試験後にG05を通す。SF感だけで合否を決めない。

# 07 — セキュリティ・プライバシー・安全な解析

## 1. 信頼モデル

対象はユーザー自身が作成した、または解析の権限がある試料。正当な研究用途でも入力が安全とは限らない。ファイル本体、ファイル名、メタデータ、派生物、パーサ出力、外部ルールを非信頼として扱う。

守る資産: 原本、ユーザーの他ファイル、OS、秘密情報、解析結果の完全性、利用者の時間/資源、研究の再現性。想定攻撃者は細工した試料/記事/ルールを渡せる者。OS管理者の侵害やカーネル脆弱性まで完全防御できるとはしない。

## 3. 静的解析の境界

許可: bytes読取、特徴計算、構文解析、固定decoder、上限付き展開、限定AST書換え。禁止: 任意コード評価、JS runtimeへの入力供給、Python import/pickleロード、Officeマクロ、バイナリ起動、ネットワークの取得、OS shellへの入力埋込み。

検知のための試験的デコード、Preview、検証も同じ境界内で実施する。「安全そうだから実行して確認」は不可。信頼済みワーカーバイナリを起動することと、試料を実行することは区別する。

PHASE 07のpacker展開もまず静的な対応形式に限定。動的解析は別脅威モデル・使い捨てVM・ネットワーク禁止・サンプル取り扱い手順・追加承認が必要で、本MVPのオプションには含めない。

## 4. 隔離の具体条件

- 初期Linux案は名前空間＋seccomp＋最小ルート＋FD能力制御。MVPでは入力read-only、出力は上限監視するpipe/指定stagingだけ。
- ワーカーのsocket/connect/DNS/外部unix socketアクセスを禁止。network namespaceだけでファイル経由のIPCを防げたとしない。
- ホーム、SSH鍵、ブラウザプロファイル、環境変数のトークン、別Sessionを見せない。環境変数は最小許可リストへ置換。
- ワーカーの子起動とptraceを禁止。危険なsyscallはdeny-by-default。起動後にFDを閉じ、core dumpを無効化する。
- rlimitでCPU/アドレス空間/FD等を制限し、SupervisorがRSSを監視する。kernelが対応する場合はcgroup memory.maxも利用。RSS超過の検知遅延は実測して予算を下回る余裕を取る。
- 壁時計と出力量はワーカー自身の申告に依存しない。ブローカーが計数し、上限時はpipeを閉じプロセスツリーを終了させる。
- 起動時に外部ファイルread、書込、通信、子起動の拒否を自己診断。失敗時は解析開始不可。ユーザーにroot権限で試料を解析させる回避策を提示しない。

## 5. 資源制限と入力検査

[00](00-product-requirements.md)の上限を実装の共通policyにする。追加の暫定上限: ASTノード100万、構文深さ256、Finding1000、出力イベント1万、JSONネスト32/フレーム1 MiB。上限値はプロファイル版と共に記録する。

文字列走査は線形時間の実装を優先。バックトラックregexを非信頼の任意パターンで走らせない。解凍後にサイズを調べるのでは遅いため、ストリーミングの書込前に累積bytesを検査する。gzipのISIZEは32bitの剰余であり安全なサイズ見積りとして信用しない。

1ジョブ2ワーカー等の内部ファンアウトは行わず、MVPはジョブごとに1ワーカー、同時ジョブ2。キュー上限20、アクティブSessionのblob/staging合計200 MiB、アプリ全体の試料保存上限2 GiBを暫定値とする。永続保存済み領域が満杯なら取込を止め、明示削除を促す。予算の大きな変更は再レビューする。

## 6. 原本・出力・保存

- 原本は不変スナップショット。変換出力に実行権限を付与しない。拡張子/マジックが実行形式ならプレビュー/書出し時に非信頼であることを警告。
- 出力を自動起動・自動再帰取込しない。共有用出力のファイル名は生成し、入力のパス文字列を保存先として使わない。
- 書出し先のsymlinkや原本と同一inode/ファイル識別子を拒否。入力のハードリンクへの書込も原本破壊になることを考慮する。
- 一時データは利用者専用権限（POSIX例: directory 0700 / file 0600）。クラウド同期フォルダへの保存は推奨しない。
- OS全文索引/サムネイルの対象になりにくい管理領域を選ぶ。アンチウイルスとの競合は、保護無効化ではなくエラーとして案内する。
- セッション削除はDB/本文/索引/キャッシュを対象とし、利用者が既に外部へ書き出したレポートは自動削除しない。その区別を表示する。
- アプリ独自の保存暗号化はMVP必須にしない。機密試料はOSの暗号化ディスクで扱う方針をG00で確認。暗号化なしならUIと運用文書で明示する。
- SSDのwear leveling、バックアップ、swapのため物理的な完全消去を保証しない。core dumpを抑制してもホスト管理者からの読み取りは防げない。

## 7. 表示・外部リンク

- 試料はtext/Hexとして表示。HTML/SVG/MarkdownをそのままDOMに差し込まない。リンクは検知しても自動訪問しない。
- WebViewは同梱資産のみ許可。CSPはdefault-srcの拒否を基礎に必要なasset/IPCだけ許可し、eval/inline script/外部frameを禁止する。
- WIKIのMarkdownは許可要素限定、raw HTMLなし。エクスポートHTMLもscript/iframe/form/外部画像なし。
- `javascript:`、`file:`、独自危険schemeを拒否。WIKIのhttpsリンクはドメインを見せて確認し、アプリの権限を持つWebView内では開かない。
- コピー操作は明示的。クリップボードがOS全体や同期機能から見える可能性を説明し、本文の自動コピーを行わない。

## 8. 更新・供給網

MVPのエンジン/ルール/WIKIは同梱し、ネットワーク自動更新なし。ユーザーが別途取得した署名付きパッケージをローカルで取り込む方式を提案する。署名鍵、パッケージハッシュ、schema、対応アプリ版を確認し、失敗なら旧版を維持。

依存lockfile、SBOM、ライセンス表、既知脆弱性点検を配布前に実施する。署名は安全なロジックを保証しないため、同梱アダプターにも隔離を適用。旧版への降格は明示承認を求め、既知危険版へ自動的に戻らない。

## 9. 残余リスクと運用判断

静的パーサの未知脆弱性、OSカーネルの不備、誤検知/見逃し、出力の機密性、複雑な意味等価性は残る。高リスク試料の研究では、このアプリの隔離に加えて使い捨ての研究端末/VMを推奨する。免責の表示だけを対策の代わりにしない。

脆弱性が見つかった場合は対象アダプター無効化→該当版/影響範囲の特定→修正版・訂正告知→回帰試験。ユーザー試料を報告用に自動アップロードしない。再現に必要な最小情報を利用者が確認して共有できるようにする。

## 設計の中心原則

1. **入力を実行しない。** 読み込み・デコード・整形を理由に対象プログラムを起動しない。
2. **根拠を提示する。** ラベルだけでなく位置、観測値、反証、未解析範囲を示す。
3. **未検出は不在証明ではない。** 対応範囲と解析カバレッジを必ず併記する。
4. **原本を保持する。** すべての出力は派生物とし、変換履歴とハッシュを残す。
5. **理解と作業を往復できる。** 検知結果→WIKI→安全な教材→解析画面へ戻れる。
6. **可能性を誇張しない。** 暗号解読、元変数名の復元、未知VMの解除を自動化できるとはしない。

## 表記と仕様の優先順位

- **必須**: 受入ゲートの条件。**推奨**: 理由を記録すれば変更できる。**提案/暫定**: 承認前の初期案。
- ユーザー確定要件は00、工程ゲートは01、解析の意味は03、機械的な契約は04、安全制約は07、合否判定は08を正本とする。
- 内容が衝突したら黙って解釈せず、09の変更管理で関連文書を同じPRで更新する。安全制約の緩和はセキュリティ担当承認を必須とする。
- 本書のパス、IPC名、テーブル名は将来実装の提案。現在存在する成果物は本ドキュメント群のみ。

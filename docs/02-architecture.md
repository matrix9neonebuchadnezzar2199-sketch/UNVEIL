# 02 — システムアーキテクチャ

## 1. 推奨構成と選定理由

**提案:** ローカルファーストのデスクトップアプリ。Tauri 2系＋React/TypeScriptのGUI、Rustのコーディネータと解析ワーカー、SQLiteのメタデータ、不変blobストアを採用する。具体的なライブラリ版はPHASE 00/01のスパイクで固定する。

| 候補 | 利点 | 注意 | 判断 |
|---|---|---|---|
| ブラウザのみ | 配布容易、ファイルAPIで原本非破壊 | 大容量、ネイティブ解析、OS資源制限が難しい | デモUIには可、本体には不採用案 |
| Electron＋Node | GUI開発資産が豊富 | 配布容量、権限境界、JSランタイム攻撃面 | チーム要件によって再比較 |
| Tauri＋Rust | 軽いシェル、ネイティブI/O、プロセス統制 | WebView差、隔離は別途実装必須 | 推奨 |
| Python GUI/解析 | 研究用ライブラリが豊富 | 配布・起動、import/実行の混入管理 | 将来の隔離アダプター候補 |

Tauri自体が解析サンドボックスになるわけではない。パーサのRust実装も資源枯渇・ロジック欠陥への耐性を保証しない。

## 2. コンポーネントと信頼境界

```text
利用者
  │ ファイル選択・操作
  ▼
UI WebView（信頼しない表示層、任意パス/コマンド権限なし）
  │ 許可された型付きIPCだけ
  ▼
Coordinator（ローカルの権限を持つ小さなブローカー）
  ├─ Import Broker ── 不変スナップショット/ハッシュ
  ├─ Job Supervisor ─ タイムアウト/隔離/キャンセル
  ├─ Artifact Store ─ 派生物/由来/原本参照
  ├─ SQLite ───────── メタデータ/イベント/設定
  ├─ Report Writer ── エスケープ済み出力
  └─ Knowledge Service ─ 同梱記事/検索索引
           │ 既に開いた入力ハンドル、限定出力チャネル
           ▼
  Isolated Worker（ファイルもワーカー出力も非信頼）
    ├─ Probe / Features / Detectors
    ├─ Safe Transform Adapters
    └─ Validators
```

ワーカーからDB、UI、ユーザーホーム、外部ネットワークへ直接接続させない。結果JSON・派生物はブローカーが長さ/型/範囲/ハッシュを再検証して取り込む。UIには必要な抜粋だけ送る。

## 3. ファイル取込

1. ネイティブダイアログ/ドロップハンドラが、一度だけ使える選択トークンを生成する。フロントから自由なパス文字列は受理しない。
2. ブローカーが通常ファイルであることを検証し、シンボリックリンク、デバイス、FIFO、ディレクトリを拒否する。
3. no-followとハンドル中心I/Oで開き、同じハンドルから上限付きコピーとSHA-256計算を行う。コピー後にサイズ/mtime/ファイル識別を再確認する。
4. 処理中の変更は完全には観測できないため、解析対象は「取得したスナップショット」と明示する。異常検知時は破棄して再選択。
5. 元ファイルは一切書き換えない。原本パスはローカルの機密メタデータとして扱い、レポートには既定で含めない。
6. 自動保存はしない。既定の一時セッションでも処理用スナップショットがディスクに置かれることを取込前に説明する。

## 4. ワーカーと隔離

- MVPのLinux案: root不要のユーザー/マウント/ネットワーク/PID名前空間、読み取り専用の最小ルート、必要FDのみ継承、seccompのsyscall許可リスト、rlimit、プロセスツリーの監視。
- 上記のOS機能が無効・不足の場合はfail-closed。隔離なしモードへ自動フォールバックしない。
- `exec`は信頼済みワーカーバイナリ起動時だけに限定。ワーカー起動後の対象実行・子プロセス起動は拒否する。
- パーサ/デコーダを1ジョブ専用プロセスで動かし、ジョブ終了時に終了する。再利用による試料間の状態残存を避ける。
- 制御は長さ付きJSONフレームとバイナリチャネル。stdoutの自由形式ログをプロトコルに流用しない。最大JSONフレーム1 MiB、ネスト32、イベント数1万を暫定制限とする。
- Windows/macOSは同等のファイル/通信/子起動の強制制限が実証されるまで解析を出荷しない。Job Objectだけで通信隔離できるとはしない。
- 詳細な拒否試験は[07](07-security.md)。

## 5. 保存とトランザクション

将来のアプリ管理領域の論理構成（本設計作業でこれらのディレクトリは作成しない）:

```text
workspace/
  metadata.sqlite
  sessions/<session-id>/blobs/<sha256>
  sessions/<session-id>/staging/<job-id>/
  knowledge/<pack-version>/
  logs/  # 本文/鍵/原本パスを含めない
```

- SQLite: セッション、Artifact、Finding、Plan、変換Step、検証結果、イベント、記事参照を格納する。サンプル本文をDBに重複格納しない。
- Blob: セッション内のみ重複排除。セッションをまたぐ共有を避け、削除の影響と存在情報の漏えいを限定する。
- commit手順: stagingへ上限付き書込→ハッシュ計算→fsync→原子的rename→DBトランザクションで参照確定。途中失敗なら参照しない孤立blobを次回起動時に回収する。
- 終了結果と最終イベントは同じDBトランザクションで記録。イベント再送で最終状態を二重更新しない。
- 一時セッション: 正常終了で削除、クラッシュ後は次回起動時に所有権・実行中ジョブを確認して掃除。即時完全消去やSSD上の物理消去を保証しない。
- 永続セッション: 明示保存後に保持。削除には原本スナップショット/派生物/索引/ログの対象範囲を表示する。
- 秘密キーを必要とする将来変換はキー参照だけ永続化し、再現時の再入力を要求。生鍵をログ/レポートに記録しない。

## 6. 解析エンジン構成

- Probe: 型・文字コード・coverageを返す。
- Feature Extractor: 長さ・字種・局所分布・AST形状など観測値を返す。ここで「悪意」を判定しない。
- Detector: 観測値から方式候補と根拠を返す。原本に変更を加えない。
- Hypothesis Resolver: 重複/矛盾/代替説明をまとめる。
- Transform Planner: 入力範囲、前提、コスト、出力/検証を見積もる。
- Adapter: 許可された決定的な変換だけ実行する。
- Validator: 可逆性、構造、規則の前提を検証する。
- Reporter: 全結果に版、範囲、限界、停止理由を結合する。

検知中の試験的デコードにもAdapterと同じ隔離/上限を適用し、副作用のある任意評価器を別名で持ち込まない。

## 7. パーサと拡張

JSパーサは構文解析だけを提供する候補を比較し、AST位置・言語版・コメント・正規化/生成の往復をスパイクで確認する。ビルドプラグイン、babel設定ファイル、package.jsonスクリプト等を入力ディレクトリから読み込まない。型/構文の評価のためにNodeやブラウザを起動しない。

MVPのアダプターは同梱・版固定・許可リスト制。宣言契約は `id / version / technique_ids / input_kinds / parameter_schema / capabilities / preconditions / limits / output_kinds / validation / license`。バイナリのハッシュも記録する。外部プラグイン配布は07以降。

## 8. 再現性と運用観測

同じスナップショット、範囲、設定、アダプター/パーサ/ルール版、決定的seedなら同じ結果を返す。日時・ランダムID・測定時間は比較対象から除外する。実行順に依存するトップ候補の順序を避け、スコア同値は安定IDで並べる。

ログはジョブID、エラーコード、処理時間、資源上限、版のみを基本とする。本文を含む診断は明示的なローカル保存とプレビューを必要とする。テレメトリはMVPでは送信しない。

## 9. 失敗時の責務

UI停止と解析停止を独立させる。ワーカー異常終了はジョブ失敗、DB書込失敗は確定処理失敗、未対応形式はサポート状態として扱う。解析が失敗してもWIKIは利用可能。UIが再起動したら最新スナップショットとイベント連番から状態を回復し、未確定stagingの内容を成功結果として見せない。

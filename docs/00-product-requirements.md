# 00 — プロダクト要件と対象範囲

## 1. 定義と価値

UNVEILは「これは難読化か」「どのような方式か」「どこまで戻せるか」を、根拠と限界を伴って調べるローカル研究GUIである。解析の出力を教材と結び付け、研究結果を別の担当者が追試できる状態にする。

| 用語 | 本製品での意味 | 混同してはならないもの |
|---|---|---|
| 難読化 | 人間・解析器による理解を困難にする表現変換 | 悪意そのもの、暗号化そのもの |
| エンコード | Base64等の表現変換 | 秘密性を保証する暗号 |
| 圧縮/パック | 容量縮小、または実行ファイルのラッピング | それだけで難読化・マルウェアとはしない |
| 検知 | 難読化や関連変換の兆候を見つける | ファイルの安全判定 |
| 特定 | 方式・亜種候補を証拠で絞る | 書いた人物や製品名の確定 |
| 解除 | 対応方式の逆変換、部分復元、可読化 | 元ソース完全復元、暗号鍵の自動獲得 |
| 検証 | 逆変換・構文・制約等のチェック | 一般プログラムの完全な意味的等価性証明 |

UIの「解除」は上位概念とし、各操作は「デコード」「展開」「整形」「限定AST書換え」と正確に表示する。

## 2. 利用者と主要シナリオ

- 研究者: 自作・許諾済みファイルを読み込み、特徴・候補・変換を比較し、レポートを再現する。
- 検証担当者: 社内試料の調査で、不明・未対応・失敗を混同せず、原本を保持して結果を共有する。
- 学習者: 年表と分類から技法を理解し、無害な教材で前後比較し、検知根拠を学ぶ。
- 知識編集者: 記事・根拠・教材・ルールの関連をレビューし、版を付けて更新する。

主要導線: ファイル選択→権限・保存説明→取込→形式判定→静的検知→根拠を確認→WIKI参照→変換候補プレビュー→承認→変換→検証→比較→レポート保存。

失敗導線も主要導線とする。例: 未対応の実行ファイル→基本メタデータのみ→未解析理由→対応する学習記事→原本を変更せず終了。

## 4. 対応範囲の段階化

初期対象OSはLinux x86_64のデスクトップを提案する。ユーザーOSが未提示のため、Windows/macOS配布を約束しない。OSを変えても同等の隔離を実現できない場合、解析機能を提供しない。

| ファイル/方式 | MVPの検知・特定 | MVPの解除支援 | PHASE 07以降 |
|---|---|---|---|
| UTF-8テキスト、BOM付きUTF-16 | 全体と文字列領域の特徴 | 厳格デコード後の表示 | その他文字コードの明示選択 |
| Base64/Base64url/Base16 | 字種・構造・逆変換整合性 | 厳格なデコード、証拠を添付 | Base32、独自アルファベット |
| percent/JavaScript escape | 文脈を確認した候補 | 選択領域を明示したデコード | 他言語のescape |
| JavaScript (.js/.mjs) | AST、長い文字列、分割、minify兆候 | 整形、純粋リテラルの連結 | 限定文字列テーブル、CFG |
| JSON/TXT/HTML/CSS | テキスト特徴、文字列候補 | 領域デコードのみ。HTMLを描画しない | 形式別解析 |
| gzip | マジックと構造、圧縮として分類 | 上限付き単一ストリーム展開 | 複合アーカイブ |
| ZIP/PDF/Office/画像 | 基本形式識別のみ | なし、内部は未解析 | 安全な抽出・メタ解析 |
| PE/ELF/Mach-O | マジック、粗いエントロピーのみ | なし、内部解析は未対応 | セクション、既知packer特定 |
| UPX等のpacker | MVPでは製品を特定しない | なし | 対応版限定のオフラインunpack |
| XOR/ROT系 | WIKI教材のみ。実ファイル推定は未対応 | なし | パラメータ既知の限定逆変換 |
| 暗号化、仮想化、自己書換え | 不明を返す。一般的兆候は記事で説明 | なし | 対象を限定して別途審査 |
| Python/PowerShell/.NET/Java | 基本メタデータ/テキスト特徴のみ | 言語固有の解除はなし | パーサごとの対応追加 |

ファイルを「選択できる」ことと「内部を解析できる」ことを別表示する。拡張子はヒントに留め、マジック・文字コード・パーサの結果を優先。MVPはディレクトリ一括取込、URL取得、添付物の自動巡回を行わない。

## 5. 初期上限・非機能条件（承認前の提案値）

- 単一入力: 最大50 MiB。テキスト/AST解析: 最大10 MiB。超過時は範囲限定の特徴抽出に留める。
- 1ジョブ: wall time 60秒、ワーカーRSS 512 MiB、同時ジョブ2、派生物累計100 MiB。
- 1変換: wall time 10秒。自動チェーン: 最大5段、全分岐合計20変換試行。
- gzip: 展開後最大50 MiB、圧縮比100倍の両方を制限。ストリーム途中でも停止する。
- 表示: テキスト初回200 KiB、証拠抜粋2 KiB、Hex/差分は仮想スクロール。全体をDOMに載せない。
- 上限は厳格に適用し、超過は正常な制限到達として返す。画面からの無制限化は禁止する。
- 中止クリックのUI応答100 ms以内、中止要求からワーカー停止まで2秒以内を目標とする。
- 参照端末、p95測定、精度評価とリリース判定は08を正本とする。現時点で性能は未計測。

## 6. 非目標・期待値

- ウイルス対策製品、侵害判定、全ファイルの完全な安全性証明ではない。
- 任意プログラムの実行、デバッグ回避、ライセンス制限回避、DRM解除はMVPに含めない。
- 強い暗号の鍵なし復号、削除済みのコメント/元変数名の完全復元を保証しない。
- 外部へのサンプル送信、クラウドAI判定、オンライン必須機能、共同編集は初期設計に含めない。
- LLMの推測による「解除成功」認定をしない。将来導入する場合も別の明示的同意と検証が必要。

## 7. 要確認事項

実装開始前に、優先OS、主対象言語/ファイル、危険試料の想定、配布形態、データ保持期間、ユーザー提示UIを確認する。未回答でも設計案は進めるが、これらをユーザー承認済みとは扱わない。決定担当・期限は[09](09-decisions-operations.md)に集約する。
